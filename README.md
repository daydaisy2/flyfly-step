# 리훨 임챌 👣

훨훨(박성혜)의 **임장챌린지**를 따라 걷는 부부의 기록 PWA.
노란 바탕 · 흰 둥근 카드 · 네이비 포인트로, 다른 앱(bubudaisy · bubulife · workout-quest)과 같은 테마입니다.
처음에는 한 줄씩 접어 두고, **눌러야 내용이 펼쳐지는** 구성입니다.

## 화면 구성

| 화면 | 내용 |
| --- | --- |
| 시즌 탭 · 영상 목록 | 상단에 **시즌1 ~ 시즌8** 탭. 영상 하나가 한 줄(번호 · 지역명 · 다녀온 지점 수). 줄을 누르면 영상 상세로 |
| 영상 상세 | 제목 · `총 9km · 180분 · 지점 2 / 9` · **유튜브**(열기 ↗) · **임장지도** · **한 장 지도**(줄을 누르면 펼쳐짐, 사진을 누르면 크게) · **지점** 세로 동그라미 |
| 지점 상세 | **네이버지도 / 네이버부동산** 버튼 · **기본 아파트 개요** · **현장사진** · **매물 세팅(표)** · **메모** (모두 접힌 줄, 눌러서 펼침) · **다녀왔어요** 표시 |

- 지점의 **동그라미**를 누르면 "다녀옴"으로 표시되고(채워진 네이비), **이름**을 누르면 지점 상세로 들어갑니다.
- **코스 번호 `1-1`, `1-2`**: 한 코스에서 단지를 여러 개 보면 지점을 **앞 지점과 같은 코스에 묶어** `1-1`, `1-2`로 나눕니다(혼자인 코스는 그냥 `1`, `2`).
  지점 수정의 `코스 번호`에서 묶고, **`이름으로 나누기`** 는 `A · B · C` 또는 `이름 (A · B · C)` 처럼 ` · , / ` 로 구분된 이름을 여러 지점으로 쪼갭니다
  (기존 메모·사진·매물은 첫 번째에 남음). 묶음의 맨 앞 지점을 빼면 뒤따르던 지점이 새 코스의 대표가 됩니다. 데이터에는 `sub: true` 로 저장됩니다.
- **지점 순서·편집**(기록 모드): 지점 목록 위의 `↕ 순서·편집`을 누르면 ▲▼로 순서를 바꾸고, 지점 사이의 `＋ 여기에 지점 추가`로
  중간(맨 앞 포함)에 끼워 넣고, ✕로 뺄 수 있습니다. 번호는 자동으로 다시 매겨지고, 다녀옴 표시·사진·매물은 지점과 함께 움직입니다.
- 지점 종류를 **아파트 단지**로 두면 개요·매물 세팅이 나오고, **그 밖의 지점**(역·학교 등)이면 링크·사진·메모만 나옵니다.
- 시즌 탭의 마지막 선택은 기억합니다. 주소는 `#s=5`(시즌) · `#v=<영상>`(영상) · `#v=<영상>/p=<지점>`(지점) 입니다.

## 🔐 입장 비밀번호

- 처음 여는 폰에서는 **입장 비밀번호**를 먼저 받습니다(6자 이상, 8자 이상 글자 조합을 추천).
  비밀번호로 **비밀 방 이름**을 계산(PBKDF2-SHA256 20만 회)해서 그 방의 데이터만 읽고 씁니다.
  서버는 방 목록을 열어 주지 않으므로, 방 이름을 모르면 기록을 볼 수 없습니다.
- 비밀번호는 코드·서버·폰 어디에도 저장하지 않고, 폰에는 계산된 방 이름만 남깁니다.
  **한 번 입장한 폰은 다음부터 바로 열립니다.** 목록 맨 아래 `이 폰에서 나가기`로 이 폰의 입장 정보를 지울 수 있습니다.
- 이 비밀번호로 저장된 기록이 없으면 "처음이라면 새로 시작"을 물어봅니다. 틀린 비밀번호를 넣어도 남의 기록은 보이지 않습니다.
- 검색에 나오지 않도록 `noindex` 표시와 `robots.txt`(`Disallow: /`)를 함께 씁니다.
- 아래 **기록 모드**의 6자리 편집 비밀번호는 그대로이며, 입장 비밀번호와는 별개입니다.
- 주의: 입장 비밀번호를 잊으면 기록을 찾을 수 없습니다(서버에도 비밀번호가 없습니다).

## 두 가지 모드

| 모드 | 설명 |
| --- | --- |
| 보기(공개) | 링크를 연 누구나 읽기만 합니다. 추가·수정·삭제 버튼이 없습니다. |
| 기록(편집) | 오른쪽 위 🔒 를 눌러 6자리 비밀번호를 넣으면 ✏️ 로 바뀌고 편집할 수 있습니다. |

- 잠금 해제 상태는 브라우저 `localStorage`(`imchall.unlock.v1`)에 기억됩니다. ✏️ 를 다시 누르면 잠깁니다.
- 비밀번호는 앱 안에 평문으로 들어 있지 않고 SHA-256 해시로만 비교합니다. (화면의 버튼을 숨기는 용도이며,
  서버 권한을 나누는 장치는 아닙니다.)
- 기록 모드에서: **＋ 영상 추가**(시즌·번호·지역명·유튜브 링크·임장일·상태·총거리·소요시간), 영상 ✏️ 수정/삭제,
  **＋ 지점 추가**, 지점 ✏️ 수정/삭제, 지도 사진 넣기·바꾸기·지우기, 현장사진 추가·삭제(사진을 크게 열어 🗑).

## 🏢 단지 기본정보 · 🧮 매물 세팅

**단지 기본정보**(지점 상세 → `기본 아파트 개요`, 네이버부동산 기준 · 단위 만원): 시군구 · 읍면동 · 연식 · 세대수 · 최고가 · 실거래가(매매) · 실거래가(전세) ·
매매호가 · 전세호가 · 조회기준일. 호가·실거래가는 시점마다 바뀌므로 조회기준일을 함께 적습니다. 갭(매매호가−전세호가)과 최고가 대비 매매호가는 자동 계산합니다.
평형·주차·용적률은 선택 항목입니다.

**매물 세팅**(`매물 세팅` 줄을 열면 표가 나옴): **매물 하나가 한 열**이고, 오른쪽으로 밀어 여러 매물을 비교합니다. 금액 단위는 **만원**.

| 묶음 | 줄 |
| --- | --- |
| 정보 | 동 · 층(총층수) · 전용면적 · 입주가능 · 세안고 |
| 세팅 | **매매 / 대출 or 전세 / 내 돈(자본)** |
| 부대 | 중개(요율 기준) · 취득(간이계산 / 직접 입력) |
| 합계 | **총투자금 = 내 돈 + 중개 + 취득** |
| 판정 | 조사 기준에 맞는지 (대상 / 제외 / 확인) |

- **대출 or 전세**: 둘 중 하나만 씁니다. 자금 조달 방식이 `생초(LTV70%)` · `LTV40%` · `직접입력`이면 **대출**(= 매매 × LTV, 대출 한도가 있으면 그 금액까지),
  `전세 끼고(갭)`이면 **전세** 금액을 씁니다. **내 돈 = 매매 − (대출 또는 전세)**.
- 월 금액은 대출일 때의 원리금(금리 기본 5% · 30년, 만원 단위 절사)입니다.
- 중개보수는 요율(기본 0.55%)로 자동 계산하고, 취득세는 1·2·3주택 간이 계산입니다(전용 **85㎡ 초과**일 때만 농어촌특별세 0.2%를 더함).
  둘 다 **직접 금액을 넣으면 그 값**을 씁니다.
- **조사 판정**: 전용 **84㎡** 국평 입주매물만 `대상`, **1~3층 · 탑층(층 ≥ 총층수) · 세안고**는 `제외`(사유 표시), 층·면적을 안 적었으면 `확인`입니다.
  기준 숫자는 코드의 `RULE` (`area: 84`, `floorMax: 3`)에 있습니다.
- 기록 모드에서 열 이름의 ✏️ 로 매물을 고치고, **＋ 매물 추가**로 열을 늘립니다.
  매물 수정 화면의 **LTV40% 복제 / LTV70% 복제**는 같은 매물을 다른 대출 기준으로 한 열 더 만듭니다.
- 같은 구조의 엑셀 서식(`임챌_정보정리_서식_초안.xlsx`)과 항목·계산식이 맞춰져 있습니다.

## 사진

- 지도·현장사진은 브라우저 `canvas` 로 줄여(지도 가로 최대 1600px, 현장사진 1100px JPEG) 올립니다.
- 영상 본문은 15초마다 통째로 받아오므로, 이미지는 본문이 아니라 `rooms/<비밀 방>-img/<키>` 노드에 따로 둡니다.
  키는 지도 `<영상>_m1` · `<영상>_m2`, 현장사진 `<영상>_<지점>_<사진>` 입니다.
- **크게 보기**: 지도·사진을 누르면 전체 화면으로 열립니다.
  가로 그림(지도)을 세로 폰에서 열면 **자동으로 눕혀서** 크게 보여 주고(`↻ 돌리기`로 되돌림), 가능한 폰에서는 화면 방향도 가로로 잠가 봅니다.
  **두 손가락으로 확대·축소, 한 손가락으로 이동, 두 번 탭하면 확대/원래대로**, `＋ －` 버튼과 마우스 휠도 됩니다. 뒤로가기·✕ 로 닫습니다.

## 데이터

- 저장 위치: Firebase Realtime Database `rooms/ic<입장 비밀번호에서 계산한 48자리>` (사진은 `…-img`).
  예전 공개 방(`imchall-public-v1`·`v2`)은 더 이상 쓰지 않습니다.
- 앱을 열면 한 번 읽고, 이후 저장할 때마다 해당 영상 노드만 `PUT`/`DELETE` 합니다.
- 다른 기기에서 고친 내용은 REST 스트리밍(EventSource)으로 받아오고, 연결이 안 되면 15초 주기로 다시 읽습니다.
- 마지막으로 받은 내용은 `localStorage`(`imchall.cache.v2`)에 남겨, 오프라인에서도 그 화면이 열립니다.

## 뒤로가기

안드로이드에서 뒤로가기를 눌러도 앱이 꺼지지 않고, 열려 있는 팝업(입력 시트 · 확인창 · 사진 크게 보기 ·
🔒 잠금 팝업)만 닫힙니다. 팝업을 열 때 `history.pushState({appModal:true})` 로 히스토리를 하나 쌓고,
`popstate` 에서 그 팝업만 닫습니다. 화면 이동(목록 → 영상 → 지점)은 일반 해시 이동이라 뒤로가기로 한 단계씩 돌아옵니다.

## 파일

| 파일 | 설명 |
| --- | --- |
| `index.html` | 앱 전체 (화면 + 잠금 + 계산 + Firebase 동기화). 외부 라이브러리 없음 |
| `manifest.webmanifest` | 홈 화면 설치 정보 |
| `sw.js` | 오프라인 캐시 (Firebase 통신은 캐시하지 않음) |
| `icon-*.png` | 아이콘 4종 (192/512, maskable) |
| `robots.txt` | 검색 노출 차단 |

## 배포

정적 호스팅(GitHub Pages 등)에 그대로 올리면 됩니다. HTTPS 에서 열어야 잠금 해제(WebCrypto)와
서비스워커가 동작합니다.
